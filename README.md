# Flower Mini App — Красноярск

MVP-заготовка Telegram Mini App: React + TypeScript, FastAPI, aiogram 3, PostgreSQL.
Включает каталог, корзину, создание заказа, Telegram initData validation, админ API,
AI-рекомендации через OpenAI-compatible API и интеграцию YooKassa SBP.

## Запуск
1. Установите Docker Desktop/Engine с Compose.
2. Скопируйте `.env.example` в `.env`; задайте BOT_TOKEN, TELEGRAM_BOT_USERNAME и ADMIN_API_KEY.
   Сгенерируйте отдельный случайный `POSTGRES_PASSWORD` длиной не менее 32 символов; Compose
   не запустит базу с пустым паролем. Не используйте пароль из примера повторно.
   Для команд администратора также задайте ADMIN_TELEGRAM_IDS. Адрес самовывоза задаётся через
   `PICKUP_ADDRESS` (по умолчанию: Красноярск, проспект Мира, 5).
3. `docker compose up --build -d` запускает PostgreSQL, backend, бота и production frontend.
4. Магазин: http://localhost:5173. Backend и frontend доступны с хоста только через localhost;
   PostgreSQL доступен только внутри Docker-сети. OpenAPI/Swagger отключены.
5. Для открытия Mini App внутри Telegram настройте Menu Button в @BotFather на публичный HTTPS URL.
   Локальный адрес не доступен Telegram-клиенту без HTTPS-туннеля.

### Временный HTTPS-туннель для теста Telegram
1. Запустите приложение через Docker Compose.
2. В отдельном PowerShell выполните `cloudflared tunnel --url http://localhost:5173`.
3. Скопируйте выданный `https://*.trycloudflare.com` адрес и укажите его в @BotFather:
   `/mybots` → бот → Bot Settings → Menu Button → Configure menu button.
4. Не закрывайте окно туннеля во время теста. Адрес временный и изменится при следующем запуске.
   Frontend проксирует `/api` к backend, поэтому для теста достаточно одного туннеля.

### Настройка бота в Telegram
1. В @BotFather выполните `/setcommands`, выберите бота и добавьте:
   `start - Открыть магазин`, `admin - Команды администратора`, `orders - Заказы`,
   `order - Детали заказа`, `stock - Остатки`, `payinfo - Информация об оплате`,
   `promo - Объявление об акции`.
2. Выполните `/mybots` → выберите бота → Bot Settings → Menu Button → Configure menu button.
   Укажите HTTPS URL приложения из шага выше и подпись, например «Открыть магазин».
3. Чтобы разрешить `/admin` и `/orders`, узнайте свой Telegram user ID и внесите его в
   `ADMIN_TELEGRAM_IDS` в `.env`. Для нескольких ID используйте список через запятую.
4. После изменения `.env` запустите `docker compose up -d --force-recreate bot backend`.
   Проверить ответ бота можно, отправив ему `/start` в личном чате.
5. Администратор может открыть `/admin`, просматривать последние заказы через `/orders`,
   менять статусы кнопками, обновлять остаток командой `/stock ID КОЛИЧЕСТВО`, отправлять
   клиенту инструкции по оплате после подтверждения через `/payinfo ID ТЕКСТ` и рассылать
   объявления об акциях через `/promo ТЕКСТ`. Перед рассылкой бот показывает предпросмотр
   и просит подтвердить действие.

### Заказы, доставка и уведомления
- Доставка стоит `DELIVERY_FEE_RUB` (по умолчанию 350 ₽); самовывоз бесплатный.
- Клиент выбирает доставку или самовывоз при оформлении. Адрес самовывоза задаётся через
  `PICKUP_ADDRESS`.
- При оформлении остаток резервируется. При отмене заказа администратором он возвращается
  в каталог; подтверждённый заказ переводит оплату в состояние ожидания инструкций.
- Для букетов с несколькими ценами в описании можно выбрать вариант. Цена проверяется и
  рассчитывается backend по каталогу; название и цена варианта сохраняются в заказе и
  отображаются администратору в Telegram и панели заказов.
- Складской учёт цветка доступен по адресу `/stock` и защищён `ADMIN_API_KEY`. Добавьте
  номенклатуру цветов, фиксируйте приход с закупочной ценой за единицу, расход и брак;
  остаток и его стоимость видны в разделе «Склад». Цена остатка считается по средневзвешенной
  закупочной цене. В «Рецептах продаж» задайте расход каждого цветка на букет (отдельно
  для вариантов). При создании заказа компоненты резервируются, при статусе «Выдан» резерв
  списывается как продажа, а при отмене освобождается или возвращается на склад; каждое действие
  отображается в журнале. Порог низкого остатка задаётся отдельно для каждой позиции; значение
  0 отключает предупреждение. Отчёт по выбранному периоду показывает приход, расход, списание
  брака и себестоимость продаж, а журнал можно выгрузить в CSV. Когда склад уже заведён,
  оформление заказа без нужного рецепта блокируется, чтобы цветы не списывались неполностью.
- Клиент получает сообщение о создании заказа и обновлениях статуса. `/payinfo` позволяет
  администратору отправить реквизиты/способ оплаты после подтверждения.
- Рассылки `/promo` отправляются пользователям, которые запускали бота, и клиентам с заказами.
  Недоставляемые подписки отключаются. Это текстовые объявления; автоматических скидок нет.

### Импорт каталога владельца сайта
Экспорт `catalog-import.json` содержит карточки каталога: названия, цены, описания, категории,
ссылки на изображения сайта и исходные ссылки товаров. Для импорта в локальную базу выполните
в PowerShell `.\scripts\import-catalog.ps1`. Скрипт заменяет активный ассортимент импортированными
позициями; новые товары создаются с нулевым остатком, пока администратор не задаст наличие.
Сейчас для импортированного ассортимента подтверждён остаток 100 штук на позицию. Варианты
букетов с отдельными ценами отображаются в селекторе, а рекомендации по упаковке остаются в описании.
Перед импортом убедитесь, что ADMIN_API_KEY в локальном `.env` является вашим секретом.

## Оплата СБП
Создайте магазин ИП в YooKassa, включите СБП, задайте YOOKASSA_SHOP_ID и YOOKASSA_SECRET_KEY,
затем PAYMENTS_ENABLED=true. Настройте webhook `POST /api/payments/yookassa/webhook`.
Webhook рассматривается только как сигнал: backend повторно запрашивает платёж у YooKassa и
сверяет статус, сумму, валюту и metadata заказа. Сначала протестируйте тестовыми ключами.
Проверьте актуальные настройки/события в кабинете провайдера перед production.

## Безопасность и ограничения
- Это MVP для локального тестирования, не готовый production без проверки.
- Используйте уникальные случайные `POSTGRES_PASSWORD` и `ADMIN_API_KEY`; `.env` не коммитьте и не отправляйте в чат.
- Frontend отдаётся production Nginx с CSP и защитными заголовками; API проксируется через него,
  а backend/БД не публикуются в локальную сеть. AI-подбор требует подписанного Telegram initData
  и ограничен восемью запросами на Telegram-пользователя за пять минут.
- Не используйте токен Telegram-бота, опубликованный в чате или логах: отзовите его в @BotFather и сохраните новый только в `.env`.
- Временный HTTPS-туннель делает приложение доступным из интернета; используйте его только для теста и остановите после проверки.
- В production нужна полноценная авторизация админов, rate limiting, аудит, резервные копии,
  мониторинг, HTTPS, управление персональными данными и проверка требований 54-ФЗ/кассы.
- Доставка пока имеет фиксированный тариф DELIVERY_FEE_RUB. Настройте зоны Красноярска, слоты,
  минимальную сумму и исключения перед запуском.
- При создании заказа цены берутся из БД, а не из браузера.
- AI выключен без AI_API_KEY; он не должен подтверждать оплату или гарантировать наличие.
- Перед публикацией заполните каталог реальными товарами, ценами и фото.

## Структура
- `backend/app/main.py` — FastAPI API, БД, заказ, AI, webhook, admin API
- `backend/app/bot.py` — aiogram 3 команды
- `backend/app/security.py` — проверка подписи Telegram initData
- `backend/app/payments.py` — YooKassa API
- `frontend/src/App.tsx` — интерфейс магазина
- `docker-compose.yml` — PostgreSQL, backend, frontend

## Оценка
Самостоятельная разработка: 0 ₽, если уже есть компьютер и интернет. Для публичного запуска обычно
нужны домен/HTTPS, сервер, резервные копии и комиссии платёжного провайдера — гарантировать
постоянный production за 0 ₽ нельзя. Оценка реализации и тестирования: 10–20 рабочих дней,
не считая срока проверки бизнеса платёжным провайдером.

## Приёмка
- [ ] Каталог и цены загружаются с backend
- [ ] Корзина и валидация формы работают на мобильном экране
- [ ] Backend сверяет товары/цены/остатки по БД
- [ ] Заказ связан с проверенным Telegram user ID
- [ ] СБП создаёт платёж только при включённой интеграции
- [ ] Webhook повторно проверяет платёж через API и сверяет сумму/валюту/order ID
- [ ] Повторный webhook не создаёт повторный заказ/повторное списание
- [ ] Админ API защищён, Telegram admin-команды ограничены ID
- [ ] Проверены ошибки, отмены, недоступность API, резервное копирование
